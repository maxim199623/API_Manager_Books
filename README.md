# API Manager Books

API Manager Books - FastAPI-сервис для управления электронной библиотекой. Проект хранит книги, главы, файлы, обложки, избранное, историю чтения, пользователей и настройки базы данных.

Сервис рассчитан на backend-сценарий: клиентское приложение или другой сервис работает с ним через REST API и WebSocket-уведомления.

## Описание

Проект предназначен для хранения и обслуживания электронной библиотеки через HTTP API. Он решает backend-задачи: хранит метаданные книг, файлы книг, обложки, главы, файлы глав, избранное, историю чтения, пользователей и настройки подключения к базе данных.

API подходит для клиентского приложения, административной панели или другого сервиса, которому нужен единый доступ к данным библиотеки и уведомлениям через WebSocket.

## Возможности

- Управление книгами: создание, просмотр, обновление и удаление.
- Загрузка и выдача файлов книг и обложек.
- Управление главами и файлами глав.
- Избранные книги и история прочитанных глав.
- Пользователи, авторизация и JWT-токены.
- Настройки базы данных через API.
- WebSocket-канал уведомлений.
- Проверка загружаемых файлов по расширению, MIME, сигнатуре и размеру.

```bash
cd API_Manager_Books
poetry install
```

Если репозиторий уже скачан, достаточно выполнить:

```bash
poetry install
```

## Настройка базы данных

Формат настроек базы данных показан в `config.example.ini`.

Минимальная SQLite-конфигурация:

```ini
[database]
backend = sqlite
echo = false

[sqlite]
path = var/app.db
```

SQLite-файл должен находиться внутри каталога `var`. Это ограничение есть в коде, чтобы путь к базе не выходил за runtime-каталог проекта.

Для PostgreSQL заполните секцию:

```ini
[database]
backend = postgres
echo = false

[postgres]
host = localhost
port = 5432
user = api_manager_books
password = change-me
name = api_manager_books
```

## Переменные окружения

Перед запуском задайте переменные окружения в текущем процессе или в системном окружении.

| Переменная | Описание | Пример |
| --- | --- | --- |
| `APP_ENV` | Режим запуска. Для штатного запуска должен быть `prod`. | `prod` |
| `APP_HOST` | Хост, на котором слушает Uvicorn. | `0.0.0.0` |
| `APP_PORT` | Порт сервера. | `1408` |
| `TLS_CERT_FILE` | Путь к TLS-сертификату. | `C:\certs\fullchain.pem` |
| `TLS_KEY_FILE` | Путь к TLS-ключу. | `C:\certs\privkey.pem` |
| `INITIAL_ADMIN_EMAIL` | Email первого администратора при пустой таблице пользователей. | `admin@example.com` |
| `INITIAL_ADMIN_PASSWORD` | Пароль первого администратора. Минимум 12 символов, не `default`. | `change-this-long-password` |

Если таблица пользователей пустая, `INITIAL_ADMIN_EMAIL` и `INITIAL_ADMIN_PASSWORD` обязательны. Без них приложение не стартует.

На Linux/macOS значения с пробелами нужно экранировать или заключать в кавычки по правилам shell.

## Запуск

Скрипты запуска проверяют окружение, устанавливают зависимости и запускают Poetry entrypoint `api-manager-books`.

Windows CMD:

```cmd
start.bat
```

PowerShell:

```powershell
.\start.ps1
```

Linux/macOS:

```bash
sh ./start.sh
```

Сервер запускается с HTTPS на порту из `APP_PORT`, по умолчанию `1408`.

```text
https://localhost:1408
```

Ручной запуск без скриптов возможен, если переменные окружения уже заданы в процессе:

```bash
poetry run api-manager-books
```

## Использование

Базовый сценарий:

1. Установить зависимости через Poetry.
2. Проверить настройки базы данных по `config.example.ini`.
3. Задать переменные окружения для запуска.
4. Запустить сервис.
5. Авторизоваться через `/users/auth`.
6. Работать с книгами, главами, файлами, избранным и историей чтения через API.

## Политика загрузки файлов

Загрузки проверяются по расширению, MIME и бинарной сигнатуре там, где формат это позволяет.

| Тип загрузки | Расширения | Лимит |
| --- | --- | --- |
| `cover` | `jpg`, `jpeg`, `png`, `webp` | 10 MiB |
| `book_file` | `epub`, `pdf`, `fb2`, `txt`, `mobi`, `azw3` | 300 MiB |
| `chapter_file` | `txt`, `md` | 5 MiB |
| `chapter_file` | `jpg`, `jpeg`, `png`, `webp` | 15 MiB |
| `chapter_file` | `pdf` | 50 MiB |
| `chapter_file` | `mp3` | 150 MiB |

Для `chapter_file` из аудио поддерживается только `mp3`. Текстовые форматы (`txt`, `md`, `fb2`) не имеют полной проверки содержимого, поэтому для них проверяются расширение, MIME при наличии и размер.
